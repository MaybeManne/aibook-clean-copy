# LessonKit — North Star

*Where this is going, and the one idea that has to survive contact with every feature.*

---

## The claim

We are not building a tool that makes interactive lessons. We are building **a compiler
for pedagogical experiences** — betting that when a lesson becomes a *compiled, replayable,
inspectable artifact* instead of a file, it stops competing with educational videos and blog
posts and starts removing the need for them.

- A video is opaque bytes. A blog post is opaque HTML. **A LessonKit lesson is structured
  data** — a JSON IR of *beats* lowered into a generic state machine, rendered through a
  swappable presentation layer.
- Because the lesson is data, the *same* artifact can be authored by a human, generated by an
  LLM, adapted to a student, reskinned by a template, exported to video, embedded, forked,
  translated, verified, and mined for analytics. A video or a webpage can do none of these.

The layered architecture already **is** this compiler:

```
authoring (frontends) → BeatSpec IR → compileLesson → Statechart
    → sampleAt / render-contract (backend) → templates (frontends)
```

Manim did this for math animation; React for UIs; LLVM for languages. Separate the *what*
from the *how* and many frontends and backends compose. **The IR is the product. Everything
else is a frontend or a backend on it.**

---

## Why this is AI-native — and how to keep it that way

AI integration is easy here for one reason: **the data model is already the shape an LLM wants
to operate on.** Generating a beat, selecting a branch, observing a learner, critiquing a
draft, tuning difficulty, translating — each is a typed operation on structured data, not
pixel manipulation. The learner's entire trajectory is an event log (`history`) plus a
blackboard, so a tutor reads *settled state*; it never scrapes a canvas.

**The governing law (do not violate):**

> Everything pedagogically meaningful lives in the typed, event-sourced IR.
> Only ephemeral rendering state lives in escape hatches.

The moment meaning hides in an un-recorded LLM call or in ephemeral 3D state, we lose replay,
analytics, verification, and AI-authorability in one stroke. For a 3D demo: *which layer /
selected head / input tokens* → IR; *camera matrices, 60 fps mouse deltas* → the viz.

## One spectrum, one artifact

Authored, adaptive-deterministic, and live-agentic lessons are **not different products.**
They are one axis — *when does generation happen, and who generates?* — and all produce the
same kind of frozen artifact, because of the `generate → freeze → replay` invariant.

| Mode | Who generates | When | Frozen result |
|---|---|---|---|
| Authored | human | up front | a lesson |
| Adaptive-deterministic | human authors branches; **the student's solution selects the edge** | authored up front, chosen at runtime | a lesson |
| Live-agentic | LLM | at runtime, per reader | a lesson |

The unlock: **a single lesson mixes modes per beat** — a hand-polished intro, an LLM-generated
practice problem seeded from the student's own mistake, an authored assessment. Generation is a
pluggable function sitting anywhere on the human↔LLM line; the frozen output is indistinguishable
in kind. No mode switch, one runtime.

**Determinism discipline.** A generated beat is recorded *as event data*
(`{ type: "beat.generated", payload: <BeatSpec> }`), so replay re-splices the identical beat
without re-calling the model. Live sessions are forward-only until frozen (the static-graph
optimizations — spine, seek, `estimatedTotal` — assume the graph is known up front); once
frozen, the concrete sequence that this reader actually saw *is* a normal lesson.

## Beats are the unit of quality

A beat is a small, typed, independently-renderable unit with a contract. That is what makes
agent-generated content *good* instead of mediocre — three things one-shot video/essay
generation can never have:

1. **Parallel specialization** — one agent per storyboard / narration / distractors / viz.
   Small jobs, each done well. (The SocraticAI decomposition win.)
2. **Per-unit adversarial verification** — critique / refute / score *each beat* against its
   contract before commit. Quality can't degrade with length, because there is no length, only
   units. This is where **verified generation** becomes core infra: generated STEM beats must
   pass a verifier before freezing. "AI-generated lesson" is only trustworthy as *verified*
   generation.
3. **Deterministic recomposition** — the typed contract lets verified units glue back safely.

**Tension to respect.** You cannot get peak visual quality + live generation + real-time all at
once. Peak quality is an *authoring-time* property (offline, multi-agent, verified). Live is
"good and adaptive," bought with speculative background generation during gates + caching.

## Templates must become a visual *language*, not just chrome

Today, template independence is real for the chrome/prose/quiz/layout (the `template/` package
is pure, renderer-generic slot + theme data). It is **not yet real for the animated / scene /
3D layer**, which is coupled to the renderers, and `registerViz` is an escape hatch with no
template story. At peak, a reskin changes the *whole* aesthetic — motion vocabulary, figure
type/color, 3D scene tokens — not just the player frame. Closing this gap is what turns "themes"
into a real template marketplace. **This is the largest current distance between vision and code.**

---

## The teacher front is "compose + direct + watch," not "edit code"

Because the IR is JSON, the studio is: compose parameterized beats visually; direct an agent to
draft within guardrails (allowed beat types, routes, tone, theme, verifier); and — uniquely —
**scrub real student sessions**, because every session is a replayable recording. Event-sourcing
gives us learning analytics for free. Custom guards/viz are a developer-extended component
marketplace, not something teachers touch.

## Peak state (the scene we're building toward)

> A student opens a backprop lesson. The opening beats are authored and agent-polished —
> genuinely beautiful. They reach a 3D computation graph, rotate it, perturb a weight. The tutor,
> watching the event stream, notices they keep avoiding the chain-rule node and *live-generates* a
> bespoke micro-explanation using the student's own wrong answer from three beats ago as the worked
> example. The teacher authored ~30% of what this student saw; agents generated the rest inside the
> teacher's guardrails, with a verifier gating the generated math. Afterward the teacher scrubs the
> session, sees the struggle, and tightens one route. The whole thing is one forkable artifact —
> hostable, embeddable, the 2D parts exportable to video, the interaction fully replayable.

## The wedge (chosen 2026-07-21: ML/AI internals)

Infrastructure visions die from having no wedge: a general platform that is nobody's favorite
tool for anything. Revolutions start narrow, prove 10×, then generalize.

**Wedge: the interactive, tutored, adaptive explainer for ML/AI internals** — the
transformer-explainer / llm-viz class (attention, backprop, optimizers, systems internals).
Because: (a) a static video is provably worse there; (b) 3D + manipulation is the entire point;
(c) *we* can author the first killer examples and credibly judge their quality; (d) the audience
is reachable and vocal. Nail this; the general platform follows.

Candidate first "10× example" (build one end-to-end):

- **Attention, felt** — a 3D attention viz the reader manipulates (type a sentence, watch heads
  light up); the tutor observes which heads they inspect and adapts.
- **Backprop you can break** — a 3D computation graph the reader perturbs; the tutor live-generates
  a remediation from the reader's own error.
- **Gradient descent playground** — a 3D loss surface the reader drops a ball on and tunes;
  adaptive challenges keyed to observed behavior.

## Non-goals (to keep scope honest)

- Not a general video editor; video export is a *backend*, not the point.
- Not "YouTube for everything" on day one — see the wedge.
- Not a place where meaning lives outside the IR — see the governing law.

---

## What has to be true (the honest risks)

- **The quality bar is brutal.** "Revolutionize" means a generated lesson beats a *good* video,
  not just that it's interactive. Multi-agent + verifiers narrow the gap; taste and pedagogy are
  a research problem, not an infra one.
- **Adoption crux:** the agentic path must make a great lesson *cheaper* than a mediocre video,
  or teachers won't switch.
- **Discipline debt:** determinism/replay, IR-validation, and sanitization stop being polish and
  become load-bearing the moment an LLM authors content. (See the review findings.)
- **3D doesn't template or export for free** — the two gaps above.
